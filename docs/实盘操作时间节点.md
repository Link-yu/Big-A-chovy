# 实盘操作时间节点

> 适用：**真实仓**（真金白银，你手动下单）。10 万模拟盘的自动化（09:37/10:07/13:07/15:07）与本文件无关，两条线互不干扰。
> 规则依据《选股框架.md》，本文件**只排时间点与动作，不新增规则**。
> 系统在任何情况下都不下单；裁决由你发起、下单由你执行。

---

## 0. 盘前准备（开盘前完成）

| 步骤 | 命令 / 动作 | 判据 |
|---|---|---|
| 1. 启动看板 | `python daily-stock-analysis/scripts/realtime_dashboard.py` | 浏览器开 http://localhost:8765 能看到界面 |
| 2. 确认网络 | `python daily-stock-analysis/scripts/network_path.py` | 直连可用即可，本机直连快于代理 |
| 3. 恢复持仓状态 | `python tools/get_position.py` | 读最新 `决策记录/YYYYMMDD.md`，拿到持仓、在盯、T+1 可卖状态 |
| 4. 确认设置 | 看板设置里 `skip_capital_ranking = false`（资金排序开启） | 报告里应出现「主力资金优选」章节 |

看板自带运行时段：**09:15–11:35、12:55–15:05**，15:15 自动关闭。09:15 起就开始产出报告，但 09:25 前是集合竞价，属预热数据，**只看不作买入依据**。

## 1. 买入日：一天的节点

### 开盘前段（禁买，只做准备）

| 时刻 | 权限 | 你做什么 |
|---|---|---|
| 09:15 | 看板启动 | 什么都不做，让它先跑两轮 |
| 09:25 | 集合竞价出开盘价 | 记录今日观察池标的的开盘价与竞价量，标出低开≥2% 的（框架第 12 行：低开洗盘仅进观察，不是独立信号） |
| 09:30–09:40 | **观察期·禁买** | 发一次 `ggp`，核对昨日在盯标的的资金是否延续、池内状态有无变化。**不下单** |
| 09:40–09:50 | **等待确认·禁买** | 再发 `ggp`。此段是交集状态机推进的关键期，看双池交集是否上到 `ENTRY_ELIGIBLE` |

### 主买窗口（一天中最重要的一段）

**09:50–10:45 第一买点**——框架认定的主要买点时段，仅 55 分钟。

| 时刻 | 动作 |
|---|---|
| 09:50 | 发 `ggp`，拿到第一批完整裁决 |
| 10:00 / 10:10 / 10:20 / 10:30 | 每 10 分钟发一次 `ggp`（见下方「节奏」） |
| 10:40 | 窗口内最后一次。之后不再新开 |

拿到 AI 裁决后，**逐只核对七项支撑**（框架第 73 行），尤其是：

- 公告门禁：`avoid` / `unknown` 一票否决
- 超大单是否为正（为负一票否决，即使主力净占比 >5%）
- 基本面：`python tools/query_financials.py <代码>`，EPS≤0 / 亏损 / 动态PE为负 → 不推真实仓
- 分笔五档承接：`python tools/query_quote.py <代码> --minute --kline`
- 买点贴合 VWAP±0.1%、回落 <1.0%

确认通过 → **你在券商 App 手动挂单**（买点区间 + 止损 + 止盈一起定好）。成交后把方向/代码/数量/价格/时间回报给 AI，才会记入决策记录。**没有回报就不算成交。**

### 盘中监控段

| 时刻 | 权限 | 你做什么 |
|---|---|---|
| 10:45–11:30 | 早盘确认期，正常仓位 | 持仓监控为主。发 `ggp` 核对已建仓的资金是否衰减、板块是否退潮 |
| 11:30–11:35 | 看板仍产出，但 11:30 后按午休处理 | 收尾，记下上午结论 |
| 11:35–12:55 | 看板停止 | 午休。可整理上午的决策记录 |

### 午后（窗口更短，仓位减半）

| 时刻 | 权限 | 你做什么 |
|---|---|---|
| 12:55 | 看板恢复（但 13:00 前仍属午休） | 等 |
| 13:00 | **午后回流**，13:00–13:45 **仓位减半** | 发 `ggp`。此段买点若成交，仓位按框架减半 |
| 13:15 / 13:30 | 同上 | 每 15 分钟一次 |
| 13:45 | 进入**午后尾段**（正常仓位） | 发 `ggp`。尾段是新开仓的最后机会段 |
| 14:00 / 14:15 | 同上 | 每 15 分钟一次 |
| **14:20** | **停止新增开仓**（框架第 27 行） | 之后只看不买。继续持仓、板块退潮、在盯清单、明日观察池监控 |
| 14:20–15:00 | 仅持仓管理 | `python tools/watch_sector.py <代码> auto --date YYYYMMDD --from 1420 --buy-count N` 查板块退潮 |

### 收盘

| 时刻 | 动作 |
|---|---|
| 15:00 | 收盘 |
| 15:05 | 看板停止产出 |
| 15:15 | 看板自动关闭 |
| 收盘后 | 发「复盘」或 `/盘中 复盘`：核算实际/模拟执行结果、检查信号衰减与板块退潮、更新结构化持仓快照、写次日 T+1 计划 |

## 2. 离场日：次日早盘的三个节点

T+1 买入当日不可卖。可卖后的处置顺序（框架第 39–41 行）：

| 时刻 | 判据 | 动作 |
|---|---|---|
| **09:25** | 集合竞价出开盘价 → **开盘价低于止损线**，或**已触发退潮且开盘未回暖** | 判定为优先退出，准备 09:30 开盘立即出，**不等 09:45** |
| **09:30** | 开盘 | 上述条件命中 → 立刻手动卖出。09:25–09:30 交易所不接受申报，所以只能等开盘 |
| **09:30–09:45** | 常规处置 | 触及止损或风险退出条件 → 按计划出；达到 **+2% 止盈** → 按计划兑现 |
| **09:45** | **常规退出截止** | 未达目标也按计划退出。**不因等待目标延长持有**（框架第 41 行） |

板块退潮对照（以买入时同板块入池数为基准，框架第 46–53 行）：

| 退潮状态 | 处置 |
|---|---|
| 入池数归零 | 最高级预警 → 次日优先退出，开盘未回暖不等 09:45 |
| 降至基准 <50% 且 5 分钟转负 | 退潮预警 → 按可卖状态处理 |
| 下降但 ≥50%，或 <50% 但 5 分钟未转负 | 继续观察，不加仓 |
| 维持或上升 | 共振维持，仍须查其他风险 |

## 3. 节奏建议：ggp 发多密

**结论：主买窗口内每 10 分钟一次，其余时段 15–30 分钟一次。**

理由：SKILL.md 规定**盘中报告超过 10 分钟就要标时效问题**，而看板约 1.5 分钟出一份报告。间隔超过 10 分钟，你手里的结论就已经不是当前市场的事实了。

固定节奏：

- 09:30、09:40（准备，不下单）
- 09:50、10:00、10:10、10:20、10:30、10:40（**主买窗口，最密**）
- 11:00、11:25（持仓监控）
- 13:00、13:15、13:30（午后回流）
- 13:45、14:00、14:15（午后尾段）
- 14:30、14:50（仅持仓）
- 收盘后一次复盘

用 `ggp` 时它读的是**上次提问到当前的全部快照**，不是最新一份——所以间隔越短，单次处理的报告越少、越快。

## 4. 硬性边界（别越线）

| 规则 | 内容 |
|---|---|
| 绝不补仓 | 框架第 17 行。已持仓标的不加仓，不存在"减半仓位即可追价"的豁免 |
| 区间外不追高 | 买点只在给定区间内，出了区间就放弃 |
| 禁用当日卖出 | T+1 买入当日即使触发止损，也只记预警 + 次日优先退出计划，**不给当日卖出指令** |
| 预测 ≠ 规则 | 只输出规则结果，不写"我觉得会涨" |
| 观察池 ≠ 可买 | 入 watchlist 不等于可买，次日仍需盘中重新核验资金、承接、共振 |
| 实验类别不升级 | `coalition` / 观察池突破 / `sector_boost` 未转正前仅模拟，不得放行真实仓 |

## 5. 定时提醒（钉钉）

`tools/live_alert.py` 已按上表配好 **8 个定时任务**，到点自动发钉钉，不需要你盯时钟。任务名统一带前缀「A股实盘·」。

| 时点 | 任务名 | 会不会发 |
|---|---|---|
| 09:26 | A股实盘·竞价与离场判据 | **仅当**有真实仓持仓或 T+1 计划时发 |
| 09:50 | A股实盘·主买窗口开启 | 必发（窗口开启信号） |
| 10:20 | A股实盘·主买窗口中段 | **仅当**出现正式门槛全过候选时发 |
| 10:40 | A股实盘·主买窗口末段 | 同上 |
| 13:00 | A股实盘·午后窗口 | 必发（含「仓位减半」提示） |
| 13:45 | A股实盘·午后尾段 | 必发（新开仓最后机会段） |
| 14:20 | A股实盘·停止开仓 | 必发 |
| 15:00 | A股实盘·收盘复盘提醒 | 必发（汇总真实仓/模拟仓数量） |

**判定全部在脚本内完成**，定时任务只负责唤醒，不参与判断——结果可复现，也不消耗模型额度。

⚠️ **提醒里的候选不等于可买**。它只表示「报告层面正式门槛全过」（类A/B、主力>5%、5分钟增量达标、回落<1.0%、站上均价线、超单主导、资金有效流入、板块共振），**基本面盈利与分笔五档尚未核验**。收到提醒后仍须发 `ggp` 走完七项支撑。

排查与自测：

```bash
python tools/live_alert.py check --at 10:40   # 模拟某时点判定，只打印不发
python tools/live_alert.py test               # 发一条钉钉连通测试
```

- 配置在 `tools/alert_config.json`（含 webhook，**已 gitignore，禁止上传**）。
- 该钉钉机器人启用了「自定义关键词」，当前关键词是 **`每日复盘`**，消息尾部会自动补一行「（通道标识：每日复盘）」。想让它更贴合，可去钉钉后台把关键词改成「实盘」，再同步改配置里的 `keyword` 字段。
- 关掉某条提醒 = 停用对应自动化任务；全部关掉不影响看板与筛选。
