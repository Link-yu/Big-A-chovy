## 2. 三个入口怎么选

| 入口 | 适合场景 | 启动命令 | 地址 |
|---|---|---|---|
| **Web 工作台**（v0.7.1 新增，推荐） | 手动跑一次筛选、翻报告库、用工具箱；Windows 首选 | `python daily-stock-analysis/scripts/web_workbench.py` 或双击 `启动工作台.bat` | <http://localhost:8765/workbench> |
| **实时看板** | 交易时段自动刷新、盯盘中快照 | `powershell -ExecutionPolicy Bypass -File "daily-stock-analysis\启动实时看板.ps1"` | <http://localhost:8765> |
| **命令行筛选** | 一次性出报告、脚本化、要 JSON | `python daily-stock-analysis/scripts/a_share_daily_screen.py --mode all --format md` | 输出到 `筛选结果/` |

两个网页入口共用同一服务：`/` 是实时看板，`/workbench` 是工作台。

### 2.1 Web 工作台

```powershell
python daily-stock-analysis/scripts/web_workbench.py                 # 默认只监听本机，自动开浏览器
python daily-stock-analysis/scripts/web_workbench.py --no-browser    # 不自动开浏览器
python daily-stock-analysis/scripts/web_workbench.py --port 8899     # 换端口
python daily-stock-analysis/scripts/web_workbench.py --host 0.0.0.0  # ⚠ 开放局域网（含个人数据，仅可信网络）
python daily-stock-analysis/scripts/web_workbench.py --no-dashboard-refresh  # 只用手动筛选，关掉看板自动刷新
```

- 工作台 = 本次任务参数（只影响这一次手动筛选）；看板顶部开关 = 看板默认（持久，影响每轮自动刷新）。改错地方是常见坑。
- 同一时刻只允许一个任务跑筛选：被占用时页面会说明原因，不会静默失败。

### 2.2 实时看板（Windows）

```powershell
# 启动：后台运行 + Edge 打开页面；日志在 daily-stock-analysis\logs\
powershell -ExecutionPolicy Bypass -File "daily-stock-analysis\启动实时看板.ps1"
powershell -ExecutionPolicy Bypass -File "daily-stock-analysis\启动实时看板.ps1" -NoBrowser   # 只启服务
powershell -ExecutionPolicy Bypass -File "daily-stock-analysis\启动实时看板.ps1" -Stop         # 停止
powershell -ExecutionPolicy Bypass -File "daily-stock-analysis\启动实时看板.ps1" -Port 8899    # 换端口

# 定时启动（默认工作日 09:15，任务名 AShare-Dashboard-0915）
powershell -ExecutionPolicy Bypass -File "daily-stock-analysis\注册看板定时任务.ps1"
powershell -ExecutionPolicy Bypass -File "daily-stock-analysis\注册看板定时任务.ps1" -Unregister
powershell -ExecutionPolicy Bypass -File "daily-stock-analysis\注册看板定时任务.ps1" -At "09:20" -TaskName "AShare-Dashboard-0920"
```

运行时段：**09:15–11:35、12:55–15:05**，**15:15 自动关机并把当日报告归档到 `筛选结果/YYYYMMDD/`**，因此**下一个交易日必须重新启动**（定时任务可代劳）。工作日 15:15 后手动启动会立即退出，属预期行为。计划任务按星期触发，**不识别法定节假日**。

看板本机接口：

```powershell
curl.exe -s http://localhost:8765/api/data     # 最新完整 JSON
curl.exe -s http://localhost:8765/api/status   # 运行状态、数据时点、下次刷新
curl.exe -s http://localhost:8765/api/md       # 最新 Markdown 报告
```

### 2.3 命令行筛选

```powershell
# 默认：严格双池
python daily-stock-analysis/scripts/a_share_daily_screen.py --mode strict --format md

# 一次出全部模块
python daily-stock-analysis/scripts/a_share_daily_screen.py --mode all --format md --top 15

# 存 JSON 供其他程序读
python daily-stock-analysis/scripts/a_share_daily_screen.py --mode strict low watchlist --format json --save "$env:TEMP\screen.json"

# 加入创业板/科创板（默认只筛沪深主板）
python daily-stock-analysis/scripts/a_share_daily_screen.py --mode all --boards main chinext star
```

| 参数 | 作用 |
|---|---|
| `--mode all / strict / low / watchlist` | 全部 / 严格双池 / 低吸 A·B·C / 明日观察池 |
| `--boards main chinext star` | 交易板范围，默认 `main`；所选板**统一参与完整筛选**（同一门槛），未选板不产生新增候选 |
| `--format md / json` | 输出格式（写盘时文件名不变，内容为 JSON） |
| `--top N` | **只影响展示行数**，不影响状态机输入（v0.7.0 已修正） |
| `--save 路径` | 额外存一份到指定路径 |
| `--network-mode auto/direct/proxy` | 取数路径：实测择优 / 仅直连 / 仅代理 |
| `--skip-announcements` | 跳过公告风险检查（**不建议**，正式筛选强制开启） |
| `--skip-capital-ranking` | 跳过主力资金优选章节 |
| `--workers N` | 日 K 并发数 |

> `--mode` 只决定「输出哪些模块」，**不放宽任何门槛**。

## 3. 一天的节奏（真实仓）

来源：[docs/实盘操作时间节点.md](实盘操作时间节点.md) 与 `tools/rule_config.py` 的执行窗口。**系统在任何情况下都不下单。**

| 时刻 | 阶段（rule_config） | 权限 | 你做什么 |
|---|---|---|---|
| 09:15 | 看板启动 | — | 让它先跑两轮；确认「主力资金优选」章节存在 |
| 09:25 | 集合竞价 | 只看 | 记录观察池开盘价、竞价量，标出低开 ≥2% 的 |
| 09:30–09:40 | 观察期·禁买 | **禁买** | 发一次 `ggp`，核对昨日在盯的资金是否延续 |
| 09:40–09:50 | 等待确认 | **禁买** | 再发 `ggp`，看交集状态机是否推进到 `ENTRY_ELIGIBLE` |
| **09:50–10:45** | **第一买点窗口** | 主买窗口 | `ggp` 每 10 分钟一次；逐只核对七项支撑后再手动挂单 |
| 10:45–11:30 | 早盘确认期 | 持仓监控 | 查资金衰减、板块退潮 |
| 11:30–13:00 | 午休 | — | 整理上午决策记录（看板 11:35 停、12:55 恢复） |
| 13:00–13:45 | 午后回流·**仓位减半** | 可买 | `ggp` 每 15 分钟一次，成交按框架减半 |
| 13:45–14:20 | 午后尾段 | 可买 | 新开仓的最后机会段 |
| **14:20–14:40** | 尾盘风控·**禁新仓** | 只看 | 持仓管理、板块退潮、明日观察池 |
| 14:40–15:15 | 收盘 | 只看 | 15:05 看板停止产出，15:15 自动关机 |
| 收盘后 | — | — | 发「复盘」；`python tools/watch_sector.py ...` 查退潮；写次日 T+1 计划 |

**次日离场（T+1）**：

| 时刻 | 判据 | 动作 |
|---|---|---|
| 09:25 | 开盘价低于止损线，或已触发退潮且开盘未回暖 | 优先退出，**不等 09:45** |
| 09:30–09:45 | 触及止损 / 风险退出 / 达到 +2% | 按计划执行 |
| **09:45** | 常规退出截止 | 未达目标也退出，**不延长持有** |

硬边界：**绝不补仓**；区间外不追高；买入当日不可卖（T+1）；止损 −3~4%、止盈 +2%、单股上限 ≤1/4。

## 4. 与 AI 协作（`ggp` / 盘中 skill）

入口：[skills/盘中/SKILL.md](../skills/盘中/SKILL.md)，规则一律引用 [选股框架.md](../选股框架.md)。

| 你说 | AI 做什么 |
|---|---|
| `ggp` | 一条龙：读**上次提问到现在全部报告** → 盘问候选与持仓（分笔五档、基本面、板块）→ 四层裁决 → 落盘 |
| `/盘中 决策 1030` | 回放指定时点及必要前序快照，不用之后的数据冒充当时事实 |
| `/盘中 盘问 600519` | 单股：资金、盘口、基本面、买点、盈亏比，再给规则结论 |
| `/盘中 复盘` | 核算实际/模拟执行、信号衰减、板块退潮、更新持仓快照与次日计划 |

**四层输出**（必须分层，不得笼统写「空仓」）：① 真实仓可开仓 ② 模拟仓可买 ③ 仅观察/真实仓暂不开 ④ 完全空仓。

**真实仓建议必须展示七项支撑**：板块主线与共振 / 主力与超大单主导 / 分笔五档与主买比 / 买点与 VWAP 贴合 / 今年盈利·EPS·动态 PE·YTD / 模拟验证状态 / 买点区间·止损·止盈·盈亏比·T+1 计划。

**成交必须回报**：方向、代码、数量、价格、时间——没回报就不算成交，持仓只以最新 `决策记录/YYYYMMDD.md` 为准。

## 5. 模拟盘（固定 10 万 · 操作手册见 [docs/模拟盘操作手册.md](模拟盘操作手册.md)）

定位：**资金曲线验证器**（考核净值/回撤/胜率），与「信号样本采集模拟仓」（资金笔数不限）职责隔离，**不参与真实仓放行**。

| 项 | 值 |
|---|---|
| 本金 | 100,000 元（`tools/sim_data/sim_account.json`） |
| 仓位档 | S 固定 1 手 / A 1/40 / B 1/10；**1 手起步**；单股上限 1/4；单日最多新开 5 只；不加仓 |
| 买入门槛 | 正式全过 **或** 框架已许可的实验类别（回落放宽、`coalition`、观察池突破、`sector_boost`） |
| 一票否决 | 公告 `avoid`/`unknown`、超大单为负（模拟盘同样不豁免） |
| 离场 | 止损 −3.5%（极限 −4.0%）、止盈 +2%、T+1 当日不可卖、次日 09:30–09:45（09:45 截止） |
| 窗口修正 | 13:00–13:45 手数减半；跨周目标仓位减半（待验证项） |

```powershell
python tools/sim_account.py status            # 账户/持仓/净值
python tools/sim_account.py scan              # 可开仓清单（只读，不写账本）
python tools/sim_account.py nav               # 净值曲线
python tools/sim_account.py check-exit        # 检查离场
python tools/sim_account.py auto --dry-run    # 按当前时段自动裁决（先干跑）
python tools/sim_account.py open --code 600519 --tier A --dry-run    # 手动开仓（干跑）
python tools/sim_account.py close --code 600519 --reason 止盈 --dry-run
python tools/sim_account.py settle / sync     # 日终结算 / 写回决策记录快照
```

自动运行 4 次（09:37 离场、10:07 早盘买入、13:07 午后买入、15:07 结算）由自动化任务驱动，**判定全部在脚本内完成**。

> 纪律：买卖与仓位**一律走脚本**，不得由语言模型自行决定；**不得用 `--force` 绕过窗口与门槛**。

## 6. 钉钉定时提醒（`tools/live_alert.py`）

```powershell
python tools/live_alert.py check --at 10:40   # 模拟某时点，只打印不发
python tools/live_alert.py auto               # 按时点判定并推送（定时任务调用）
python tools/live_alert.py auto --dry-run     # 不实际发送
python tools/live_alert.py test               # 钉钉连通测试
```

8 个时点：09:26 竞价与离场判据（仅有持仓/T+1 计划时）｜09:50 主买窗口开启（必发）｜10:20、10:40 窗口内（仅当有正式门槛全过候选）｜13:00 午后窗口（必发）｜13:45 午后尾段（必发）｜14:20 停止开仓（必发）｜15:00 收盘复盘（必发）。

配置：`tools/alert_config.json`（含 webhook，**已 gitignore，禁止上传**）；机器人关键词为 `每日复盘`，消息尾部自动带通道标识。

> ⚠️ 提醒里的候选**只代表报告层面正式门槛全过**，基本面盈利与分笔五档尚未核验，**不等于可买**；收到提醒后仍要走完 `ggp` 七项支撑。

$env:A_SHARE_STATE_DIR  = "$env:TEMP\e2e\state"     # 资金快照/交集/观察池突破/K线缓存/冷却

## 9. 网络与代理

**本机现状（2026-10-10 实测）**：东财**标准路由已全部下线**，`/webguest` 路由全部可用；直连约 950ms。

```
FAIL clist standard        OK clist webguest (rows=100)
FAIL ulist standard        OK ulist webguest
FAIL fflow standard        OK fflow webguest
FAIL stock.get standard    OK stock.get webguest
                           OK push2 trends2 webguest
```

- 排查命令：`python daily-stock-analysis/scripts/network_path.py`（路径择优诊断）、`python tools/verify_em_webguest.py`（各路由体检）。
- 配置唯一来源：`daily-stock-analysis/scripts/proxy_ports.json` 的 `candidate_ports`，与 `keep_proxy_alive.sh` 共用——**换代理软件只改这一处**。
- **本机为空数组 `[]` = 明确禁用全部本机代理端口**（直连可用）。⚠️ 升级或重写 `network_path.load_candidate_ports()` 时必须保留这个语义：上游 v0.7.1 会把空数组回落成 `(7890, 7897)`，而 7890 无监听、7897 出口是**日本东京**，会让引擎全程走海外出口、单轮跑满超时、看板退化为重放旧快照（2026-09-21 事故）。`test_network_path.py` 有对应回归用例。
- 候选端口只允许加「本机常驻、国内出口」的端口；**海外出口对东财行情接口是纯负资产**。
- 超时：`SCREENING_TIMEOUT = 210`（本地值；本机健康轮次 92~163s，上游 120s 会误杀正常轮次）。
- 探测失败时：东财不通会再看新浪；两家都不通才跳过本轮并保留旧快照；界面「强制刷新」视为探测通过。

## 10. 故障排查

| 现象 | 先查什么 |
|---|---|
| 看板不刷新 / 一直「筛选中」 | `/api/status` 的 `last_run_time`、`preserve_snapshot`、`proxy_unavailable`；跑 `network_path.py` 与 `verify_em_webguest.py`；看 `daily-stock-analysis\logs\` |
| 报告停在旧时点 | 数据时点会写在报告头部「数据时间」与 `/api/status` 的 `data_timestamp`；降级轮次不要当完整实时结果用 |
| 8765 端口被占 | `Get-NetTCPConnection -LocalPort 8765 -State Listen`；用 `启动实时看板.ps1 -Stop`，或换 `-Port` |
| 盘中取报告取错日期 | 报告盘中平铺、收盘归档，**不带日期的默认扫描会命中旧日期**；一律显式带 `--date` |
| 筛选结果为空 | 先按 7.6 排查解析与网络，别直接当成「没有候选」 |
| 中文输出乱码 / `UnicodeEncodeError` | 已给 `sim_account.py`、`live_alert.py`、`validate_consistency.py` 加了 UTF-8 重配置；其他脚本仍可能受影响，可临时 `$env:PYTHONUTF8=1` |
| 工作台页面 404 | `/workbench` 只在 `web_workbench.py` 下存在；只跑 `realtime_dashboard.py` 时只有 `/` |
| 定时任务休市日也启动 | 计划任务只会按星期触发，**不识别节假日**，属预期 |

## 11. 隐私与 GitHub 同步

```powershell
git status --short --ignored        # 确认私有目录是 !!（ignored）
git check-ignore -v 筛选结果/ 决策记录/ tools/sim_data/ tools/alert_config.json
git add -A; git diff --cached --name-only   # 提交前逐行看，确认无报告/持仓/账户/密钥
```

- 不要用 `git add -f` 强推被排除的文件。
- `origin` = `git@github.com:Link-yu/Big-A-chovy.git`（你的 fork）；`upstream` = `https://github.com/LuQTest/Big-A-chovy.git`。
- 判断远端有没有私有数据：`git ls-tree -r origin/<分支> --name-only | Select-String '筛选结果|决策记录|sim_data|alert_config|shadow_data'`（应为空）。

## 12. 已知限制与待验证项

- 计划任务不识别法定节假日；休市日照常启动（不产生有效新数据）。
- 看板 15:15 自动关机，**下一交易日需重新启动**。
- 筛选范围默认仅沪深主板；勾选创业板/科创板后统一门槛参与筛选，2026-09-30 前的旧快照口径不同，**不要跨口径比较**。
- 交易板范围、回落放宽、`coalition`、观察池突破、`sector_boost`、`divergence_leader`、跨周减仓等均属**待验证项**，各需 20 个完整结算样本才评估转正；未转正前**仅模拟**，不得放行真实仓。
- 历史分钟级目标（T+1 核验）不保证可追溯，取不到时会明确返回不可用，**不允许用当前数据替代历史目标**。
- 上游接口随时可能调整：出现取数失败先跑 `verify_em_webguest.py`，再按 [docs/东财请求频率与限流.md](东财请求频率与限流.md) 区分「限流 / 路径下线 / WAF 拦截」，不要靠改代码或加大重试硬顶。
